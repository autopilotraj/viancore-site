Oracle October 2026 CPU: What PeopleTools Admins Need to Do

89 PeopleTools fixes for releases 8.61 to 8.63. Each priority CVE in plain language, what it can do, and a workaround until you patch, including guidance for 8.60 and older.

01 · Summary

The Oracle October 2026 Critical Patch Update, released 20 October 2026, includes 89 security fixes for PeopleTools 8.61 to 8.63. PeopleTools was hit by a zero-day in June 2026, so this cycle needs more urgency than a routine quarterly patch.

This brief lists each high-priority CVE with a plain description, its impact, and a workaround for systems that cannot be patched yet. That includes PeopleTools 8.60 and older, which receive no fix for any of these.

Key actions.

  • Patch internet-facing PIA, Integration Broker and Report Repository web servers first, within 14 days.
  • The highest risks are Logstash (9.8, no login) and SQR (9.6, any signed-in user).
  • Block /PSEMHUB/* and /PSIGW/HttpListeningConnector from the internet now. These paths were used in the June attacks.
  • On 8.60 or older, no patch is available. See section 05.

  • The same components keep appearing. EMHub, Integration Broker and PIA web components were fixed in June, August and October. Harden them regardless of patch level.
04 · Priority CVEs

Each card gives the CVE, what the component does, the impact, and a workaround to use until the patch is applied. Oracle does not publish exploit details for its own code, so impact notes are based on Oracle's scoring and how each component is used in a typical PeopleSoft environment.

Oracle's guidance is that blocking network access and removing unneeded privileges can reduce risk until patches are applied, but neither is a long-term solution. Test every workaround outside production first, since some can break features that are in use.

Tier 1 · Fix first
CVE-2026-33466Logstash (bundled)9.8 Critical
No login · Network · 8.61 to 8.63
What it is

PeopleTools includes Logstash as part of the search and PeopleSoft Health Center stack. Logstash does not validate file paths when it extracts an archive, so a crafted archive can write files anywhere Logstash has access.

Impact

Full takeover of the server running Logstash. With automatic pipeline reload turned on, a planted file can run as code. The patch also fixes 31 other CVEs in Logstash libraries.

Workaround
  • If Health Center or Insights is not in use, stop Logstash and disable it at boot.
  • If it is in use, allow Logstash ports only from the search host and confirm it pulls only from sources you control.
  • Set config.reload.automatic: false in logstash.yml.
CVE-2026-101420, 101421, 101428SQR9.6 Critical
101421 needs no login · 101420 and 101428 need any valid login · Network · 8.61 to 8.63
What it is

SQR is the batch reporting engine Process Scheduler runs for most delivered reports.

Impact

101420 (9.6): any user who can sign in, including employee, student or supplier self-service users, can read and change all data PeopleTools can reach. Oracle marks it as scope changed, so the impact can extend beyond PeopleTools.

101421 (7.5): read all accessible data without a login.

101428 (7.5): full takeover by a signed-in user. Harder to exploit.

Workaround
  • Remove SQR process groups from self-service, student, supplier and guest permission lists (PeopleTools > Security > Permissions & Roles > Permission Lists > Process tab).
  • Review SQR runs by user for the last 90 days and remove access with no business need.
  • Keep Process Scheduler servers off network segments end users can reach directly.

Also fixed in this component: CVE-2026-101429 (7.0), 101426 (6.9), 101419 (6.5), 101425 (2.5). 101429 and 101426 need local server access.

CVE-2026-101390, 101411Business Interlink8.1 High
No login · Network · Difficult to exploit · 8.61 to 8.63
What it is

Business Interlinks is the older way PeopleCode called external systems, before Integration Broker. Many sites no longer use it, but it is still delivered and deployed.

Impact

Full takeover without a login. Oracle rates both as difficult to exploit, which means specific conditions are needed. It does not mean they are safe to ignore.

Workaround
  • In Application Designer, Find In across all PeopleCode for GetInterlink. No hits usually mean Business Interlinks are not in use.
  • If unused, block Business Interlink traffic at the web tier or WAF.
  • If used, restrict which servers can reach the endpoints those interlinks call and plan the move to Integration Broker.

Also fixed in this component: CVE-2026-101410 (7.5), 101488 (6.5, no login), 87345 (6.1, no login), 101389 (5.9, no login), 60814 (3.9).

CVE-2026-101409, 101422, 101427Report Distribution (Report Manager)8.1 High
101409 and 101427 need no login · 101422 needs a basic login · 8.61 to 8.63
What it is

Report Distribution posts reports to the Report Repository and serves them through Report Manager, usually under the /psreports/ path. It is often exposed to the same users as PIA.

Impact

101409 (7.5): read every report in the repository without a login, including payroll registers and vendor lists.

101427 (8.1): no login, but a user must click a crafted link. It can change or delete reports and crash the service.

101422 (8.1): the same impact with a basic login.

Workaround
  • Do not expose /psreports/ to the internet. Restrict it to internal, signed-in traffic at the load balancer or WAF.
  • Review Report Manager folder security and distribution lists. Reports distributed to broad roles such as PeopleSoft User are a common exposure.
  • Purge old reports from the repository on a schedule.

Also fixed in this component: CVE-2026-87410 (6.8, no login), 101418 (6.5), 91519 (6.5), 101424 (5.8), 87415 (5.3, no login), 101423 (4.3), 87416 (3.7, no login), 87412 (2.7).

CVE-2026-101431, 101430, 101432, 101433PeopleSoft Test Framework8.7 High
101431 needs a login and a user click · 101430 and 101433 need no login · 8.61 to 8.63
What it is

PeopleSoft Test Framework (PTF) records and replays test scripts. It belongs in development and test, but its permissions are sometimes carried into production through cloned roles.

Impact

101431 (8.7): a signed-in user can plant content that runs when an admin opens it, then read and change all data.

101430 (6.2), 101432 (5.3), 101433 (5.3): expose or change smaller amounts of data.

Workaround
  • Remove PTF permission lists and roles from all production users.
  • Run PTF only in non-production environments.
Tier 2 · Fix in the same cycle
CVE-2026-91497, 60968, 87348, 87418Updates Environment Management (EMHub)5.3 Medium
91497 needs no login · The others need local or admin access · 8.61 to 8.63
What it is

The Environment Management Hub (PSEMHUB) tracks environment details for PUM and Change Assistant. CVE-2026-35273, exploited in June 2026, was in this same component.

Impact

91497: change some data without a login. The score is medium, but treat it as high because attackers already target this code.

Workaround
  • Block /PSEMHUB/* from outside your network at the load balancer or WAF. Mandiant reported this does not affect normal PIA use.
  • In production, disable the EMHub service, or remove the PSEMHUB application on single-server installs, unless it is in use.
  • If the June 2026 alert was applied late or not at all, run the compromise check in section 06.
CVE-2026-101450, 70869Integration Broker7.1 High
No login, but a user must click · 8.61 to 8.63
What it is

Integration Broker exchanges messages between PeopleSoft and other systems. The gateway listener /PSIGW/HttpListeningConnector was also used in the June 2026 attacks.

Impact

Read all data and change some, if a user is led to a crafted request.

Workaround
  • Block /PSIGW/HttpListeningConnector from the internet. If partners need it, allow only their IP addresses.
  • Require authentication on every inbound node and review what the ANONYMOUS node is allowed to do.
CVE-2026-55200libssh2 (file transfer)8.3 High
No login, but needs a connection to a hostile server · 8.61 to 8.63
What it is

PeopleTools uses libssh2 for SFTP: file attachments, Integration Broker file transfers and report posting. A packet length check is missing.

Impact

A malicious or spoofed SFTP server can corrupt memory on the app or batch server and may run code there. The patch also fixes 5 related CVEs.

Workaround
  • Connect only to known SFTP servers and pin their host keys.
  • Review SFTP URLs under PeopleTools > Utilities > Administration > URLs and remove unused entries.
CVE-2026-101416PsAdmin7.5 High
No login · Same network segment only · 8.61 to 8.63
What it is

PsAdmin is the utility used to configure and start application server, Process Scheduler and search domains.

Impact

Full takeover from a machine on the same local network.

Workaround
  • Place PeopleSoft servers and admin ports (PsAdmin, Tuxedo JSL/WSL, Push Notification) on an admin-only network segment.
  • Limit OS-level logins to the servers.
CVE-2026-101434Database Server7.6 High
No login, but a user must click · 8.61 to 8.63
What it is

A flaw in the database component of PeopleTools. Oracle has not published further detail.

Impact

Crash of the database tier plus limited reading and changing of data.

Workaround
  • Allow database listener traffic only from app, batch and admin servers.
  • Admins should not open links from unknown senders while signed in to production.
CVE-2026-9076, 9563OpenSSL and Eclipse Parsson (JSON)7.5 High
No login · Network · 8.61 to 8.63
What it is

Two libraries bundled with PeopleTools. Parsson parses JSON for REST services, Fluid and Integration Broker. OpenSSL handles encryption.

Impact

A crafted request can crash or overload a server. This is denial of service, not data access. The OpenSSL patch includes 14 more OpenSSL fixes.

Workaround
  • These libraries cannot be replaced separately. PeopleTools is certified only with the versions Oracle ships, so the PeopleTools patch is the fix.
  • Until patched, set request size and rate limits at the load balancer or WAF for REST and Integration Broker traffic.
05 · PeopleTools 8.60 and Older

No patch is available. Oracle lists only 8.61, 8.62 and 8.63 as supported releases in this CPU. Oracle does not test older releases and states that earlier versions are likely affected. The June 2026 fix for CVE-2026-35273 was released for 8.61 and 8.62 only, so 8.60 systems never received it.

The workarounds in section 04 are the only protection until an upgrade. Apply them in this order:

Today
  • Block /PSEMHUB/* and /PSIGW/HttpListeningConnector from outside your network and disable EMHub in production.
  • Run the compromise check in section 06.
This week
  • Apply the Tier 1 workarounds: Logstash, SQR, Business Interlink, Report Distribution and Test Framework.
This month
  • Apply the Tier 2 workarounds and put PIA behind a WAF or reverse proxy with SSO and MFA.
This quarter
  • Approve and schedule an upgrade to 8.62 or 8.63. Use Oracle's PeopleTools lifecycle note on My Oracle Support (KA585) for the support dates.
06 · Compromise Check

If the June 2026 alert was applied late or never applied, check web servers for the indicators Rapid7 published:

  • Unexpected .jsp files under PSEMHUB.war, or new files under envmetadata/transactions.
  • Unexpected folders named logs, persistantstorage or scratchpad under PSEMHUB paths.
  • Recently changed .xml files under envmetadata/data/environment.
  • MeshCentral agents (files named meshagent) or a file named README-IF-YOU-SEE-THIS-YOUVE-BEEN-HACKED.TXT.
  • Outbound SMB (TCP 445) from PeopleSoft servers, or POST requests to EMHub or the IB listener from outside.

If any of these are found, involve your incident response team before patching. Patching a compromised system removes evidence and does not remove the attacker's access.

07 · Patching Checklist

The October PeopleTools patch for your release fixes all 89 CVEs. Patch numbers and download links are in Oracle's PeopleSoft patch availability document on My Oracle Support (CPU418).

  1. Confirm your PeopleTools release and patch level under PeopleTools > Utilities > About PeopleTools. Below 8.61, see section 05.
  2. Confirm the June alert and August update are covered. The October patch is cumulative, but verify it against CPU418.
  3. Apply the patch to a DEV copy with Change Assistant using the Apply PeopleTools Patch job.
  4. Test PIA sign-on, Fluid, Integration Broker, Process Scheduler, SQR, nVision, Report Manager and search.
  5. Patch every tier: web, app, batch, search and every Change Assistant workstation. A missed tier keeps the vulnerable binaries.
  6. Apply the separate October CPUs for WebLogic, Tuxedo, Java and Oracle Database in the same window. The PeopleTools patch does not cover them.
  7. Move to TEST, then PROD. Target internet-facing environments within 14 days and internal ones within 30.
  8. After go-live, scan the web tier and confirm the new patch level on every server.
