How to Provision an Always Free Oracle Autonomous AI Database (26ai) and Securely Share It with Developers

Creating a free database takes about five minutes. Creating one that four developers, an integration, and eventually an auditor can all trust takes a few more decisions. This guide covers those decisions: which tier to pick, how to lock the front door, how to hand out access without handing out ADMIN, and how to keep the bill at the number you planned.

In Short

Oracle Fusion SaaS gives you no database you can build in, so partner and extension work needs its own. An Always Free Autonomous AI Database on 26ai is a strong starting point for a proof of concept because it costs nothing and includes AI Vector Search. Lock it to known IP addresses, keep mutual TLS on, give every person and every integration its own account, and send the wallet and passwords through separate channels. Move to the Developer tier when you need backups or a database that will not stop itself, and to paid service before any real client data arrives. Watch the upgrade path closely, because the jump from Always Free to paid is bigger than most people expect.

01 · Why a Separate Database

Fusion Already Has a Database. You Just Cannot Use It.

This is usually the first question from a project sponsor, and it is a fair one. Oracle Fusion Cloud runs on an Oracle database, so why pay for, or even provision, another one?

Because in SaaS the database belongs to Oracle. You cannot connect to it with a SQL client, create a custom table, add a schema, or build an index. Data leaves Fusion only through supported channels such as BI Cloud Connector (BICC) extracts, BI Publisher (BIP) reports, and REST APIs. Anyone coming from PeopleSoft feels this immediately. There is no Application Designer, no custom record, and no quiet SQL fix in a back-end table.

So partner and extension work needs a database of its own. In practice it does three jobs:

Fusion Cloud stays the system of record and exposes data through BICC, BIP, or REST
↓
Oracle Integration (OIC) moves the data on a schedule or in real time
↓
Autonomous AI Database holds staging tables, APEX extension apps, and vector embeddings
↓
Results flow back to Fusion through its REST APIs, never by direct writes

The third job is the reason to choose 26ai. Oracle AI Database 26ai includes AI Vector Search, which lets you store embeddings next to ordinary relational data and query both in one SQL statement. If your proof of concept involves document search, a chatbot, or similarity matching on Fusion data, that removes the need for a separate vector store.

What the table does not tell you

Two details change the decision more than any line above.

Developer is not a faster Always Free. It has the same 30-session limit and the same 3 to 6 web user ceiling. What you are really buying is backups, a database that does not stop itself, and a clean path to paid service. If your pain is "too many people in APEX at once," Developer will not fix it.

A stopped Developer instance still bills. Oracle charges a flat hourly rate from creation until the instance is terminated. Stopping it saves nothing. Terminating it is the only off switch.

The upgrade trap Both tiers can be upgraded to paid service online, but they land in very different places. A Developer instance upgrades to 2 ECPU and 20 GB. An Always Free Transaction Processing instance upgrades to 4 ECPU and 1 TB. At list price that is roughly $490 a month versus roughly $1,100 a month if left running around the clock. If you plan to promote the POC database itself, go through Developer, or scale the instance down right after the upgrade.

03 · Provisioning

Six Decisions on One Screen

The create page in the OCI Console is short, but several choices on it cannot be changed later. Work through it in this order.

  • 1Check your home region first. Always Free databases can only be created in the tenancy's home region, and 26ai Always Free is offered only in a subset of regions. At the time of writing that list is Phoenix, Ashburn, London, Paris, Sydney, Mumbai, Singapore, and Tokyo. If your home region is not on it, you cannot get 26ai on Always Free, and the home region cannot be changed.
  • 2Create a dedicated compartment. Put the database in its own compartment, not in the root. Policies, budgets, and cleanup all become simpler when the project lives in one place.
  • 3Choose the Transaction Processing workload. It suits staging tables, APEX apps, and mixed read and write work. Lakehouse is aimed at analytics.
  • 4Turn on Always Free (or choose Developer). The toggle hides the compute and storage fields because they are fixed.
  • 5Choose version 26ai. An Always Free 19c database cannot be upgraded to Always Free 26ai later. Picking the wrong version means starting over.
  • 6Set a strong ADMIN password and store it in a password vault immediately. ADMIN is the break-glass account. Nobody should be using it day to day.
Admin habit worth keeping Subscribe to OCI Notifications for the compartment. Oracle sends warnings before an Always Free database is stopped for inactivity and before it is reclaimed. A banner in the console only helps if someone happens to open the console.
04 · Network Security

The Access List Is Your Only Front Door

Always Free and Developer databases cannot use a private endpoint or sit inside a VCN. They always have a public endpoint. That makes the access control list (ACL) the single most important security setting on the instance.

  • 1Choose "Secure access from allowed IPs and VCNs only." Never leave a shared development database on "Secure access from everywhere."
  • 2Click "Add my IP address" to add the public IP of the machine you are using. If you are on a VPN at that moment, it captures the VPN's exit address, not your home address. That is usually what you want.
  • 3Add developers later from the database details page under Network › Access control list › Edit. Add single IP addresses or CIDR ranges.
  • 4Add integration sources. If OIC or another cloud service connects to the database, its outbound IP addresses must also be on the list.
  • 5Keep "Require mutual TLS (mTLS) authentication" selected. With mTLS required, a client needs both a valid wallet and an allowed IP address. Turning it off allows wallet-less TLS connections, which removes one of your two locks.
Home IPs drift Residential IP addresses change without notice, and an ACL full of old home IPs is a list of addresses you no longer control. Prefer a fixed office range or a company VPN exit address. If you must allow a home IP, record who it belongs to and review the list monthly.
05 · Users and Least Privilege

One Person, One Account. Nobody Gets ADMIN.

This is the same principle you defend in every PeopleSoft access review. A shared login makes every audit question unanswerable, because the logs show the account, not the person. Create a named user for each developer and a separate service account for each integration, such as OIC.

CREATE USER <name> IDENTIFIED BY "<pwd>"; GRANT DB_DEVELOPER_ROLE TO <name>; ALTER USER <name> QUOTA UNLIMITED ON DATA;

DB_DEVELOPER_ROLE is a role introduced with the 23ai generation that bundles the privileges a developer typically needs (tables, views, procedures, and similar) without DBA powers. The quota line matters too. Without it, the user can log in but cannot create a table in the DATA tablespace.

AccountWho uses itPrivileges
ADMINPlatform owner only, as break-glassFull. Password vaulted, not shared
Named developerOne per personDB_DEVELOPER_ROLE plus quota
Integration service accountOIC or another systemOnly the objects it reads or writes. No web access

Turn on Web Access only for users who need Database Actions in the browser. In Database Actions it is a toggle on the user record. Each web-enabled user is another login page exposed to the internet, and on Always Free they also compete for the small pool of concurrent web sessions.

06 · Sharing Connection Details

The Wallet and the Password Never Travel Together

With mTLS, a developer needs two things to connect: the wallet (a zip file of certificates and connection settings) and their database password. Treat the pair like a key and its combination.

  • 1Download the instance wallet, not the regional wallet. The instance wallet works only for this database. You will set a wallet password during download, which protects the keystore inside the zip.
  • 2Send the zip through a restricted, expiring link in your file-sharing tool. Never attach it to email or post it in a chat channel.
  • 3Send passwords through a different channel, such as a password manager share or a phone call. If one channel is compromised, the attacker still has only half.
  • 4Tell them which service name to use. The wallet lists several. For development, _low or _tp is the right choice. _high gives one session more resources but allows fewer concurrent sessions, which works against you on a small shared instance.
  • 5Have users change their password at first login. The password you sent should not be the one they keep.
-- Force a password change at next login ALTER USER <name> PASSWORD EXPIRE;
07 · Optional: Sign In with OCI IAM

Remove a Person Once, Remove Them Everywhere

Local database passwords work, but every database you add is one more place to remember during offboarding. Mapping database users to OCI IAM identities means the person's access is controlled in one directory. Disable them in IAM and their access to every connected service goes with it.

As ADMIN, enable IAM as the external authentication provider:

BEGIN DBMS_CLOUD_ADMIN.ENABLE_EXTERNAL_AUTHENTICATION( type => 'OCI_IAM' ); END; /

Then map each person to a database user:

CREATE USER <name> IDENTIFIED GLOBALLY AS 'IAM_PRINCIPAL_NAME=<email>'; GRANT DB_DEVELOPER_ROLE TO <name>; ALTER USER <name> QUOTA UNLIMITED ON DATA;
  • 1Create an IAM group for the project's database users and add people to the group, not to individual policies.
  • 2Add a policy such as allow group <group> to use autonomous-database-family in compartment <compartment>. Oracle requires it when users connect with IAM tokens. For IAM database passwords alone it is optional, but it documents who is meant to have access.
  • 3Each user sets an IAM database password in their own OCI user profile. They connect with their IAM user name and that password, through the same wallet.
Only one provider at a time A database can have one external authentication provider enabled. If another one is already on, the call fails with ORA-20004. Adding force => TRUE switches providers, which also cuts off users of the old one, so confirm nobody depends on it first.
08 · Errors You Will Meet

What the Messages Actually Mean

Most first-week tickets on a new shared database fall into a handful of patterns. Nearly all of them are access problems that look like database problems, just like a certificate issue that shows up as a failed node ping.

09 · Controlling Costs

The Database Is Free. The Integration Is Not.

On most POCs the database is the smallest line item. The larger one is usually Oracle Integration, which moves data in from Fusion.

OIC 3 billing unit
Message packs per hour, with a 1 pack minimum even when idle
OIC Standard, 1 pack
$0.6452 per hour, about $15.48 a day
Stopping OIC
Pauses billing, but endpoints and schedules pause too
BYOL
20,000 messages per pack instead of 5,000, only with eligible licenses

Stopping an OIC instance when nobody is using it is tempting, and it does pause billing. Oracle advises against stopping instances on a nightly basis, and against stopping production at all. Lifecycle actions are blocked during patching, scheduled integrations do not run while the instance is stopped, and the connectivity agent shuts down if the instance stays stopped for more than 24 hours. Stopping for a planned week off is reasonable. A nightly stop and start script is not.

Bring your own license (BYOL) pricing is attractive on paper. Choose it only if your organization actually owns eligible Oracle Fusion Middleware licenses that are not already in use elsewhere. Using BYOL without the entitlement is a licensing finding, not a discount.

  • 1Set a budget with alerts on the project compartment, with thresholds at 50, 80, and 100 percent of plan.
  • 2Tag every resource with project and owner, so the cost report answers "whose is this?" without a meeting.
  • 3Remember the Developer rule. Stopping a Developer database does not stop its bill. Terminate it when you are done.
  • 4Delete resources when the project ends. The most expensive cloud resource is the one nobody remembers creating.
10 · Offboarding Checklist

Closing Access When People or Projects Leave

Run this when a developer rolls off, and run all of it when the project ends. Keep a dated record of each step. It is exactly the evidence an access reviewer asks for.

  • 1Drop the user, or lock it first if their objects need review: DROP USER <name> CASCADE;
  • 2Remove their IAM group membership if you use IAM sign-in.
  • 3Rotate the instance wallet. This invalidates every copy of the old zip. Use a grace period (1 to 72 hours) if remaining users need time to download the new one.
  • 4Remove their IP addresses from the access control list.
  • 5Rotate any shared secret they knew, including integration passwords, and update the integration connection.
  • 6At project end, stop or delete the database. Export anything worth keeping first. Always Free has no backups to fall back on.
11 · Lessons Learned

What Carries Over From On-Premises Administration

Free does not mean low stakes

A POC database often outlives its plan and quietly collects real data. Set it up as if an auditor will ask about it later, because eventually someone will.

The tier decision is really an exit decision

Choosing between Always Free and Developer matters less on day one than on the day you promote. Decide early whether this database will become the real one, and pick the path that lands at a sensible size.

Access control lives in three places

The network list, the wallet, and the database account each have to be granted and each have to be revoked. An offboarding that only drops the user leaves two doors open.
