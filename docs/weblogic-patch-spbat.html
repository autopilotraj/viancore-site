Applying a WebLogic Patch Using SPBAT

A generic, product-agnostic sequence for applying WebLogic patches with Oracle's Smart Patching Bundle Application Tool — treat your own application's documentation as the authority on specifics.

Overview

SPBAT (Smart Patching Bundle Application Tool) is Oracle's standard mechanism for applying WebLogic patches without going through OPatch manually for every jar. It's reliable and mostly unattended once you've staged the patch correctly, but the staging and environment-variable steps are where people go wrong. Always check Oracle's current Critical Patch Update advisory for the patch that applies to your WebLogic version before starting.

Patch steps
  • Download the applicable WebLogic patch from My Oracle Support. You need a valid company account/license with MOS to pull the software.
  • Shut down every web server domain running on the target VM.
  • Copy the patch archive from your network share to a temp directory on the target server, e.g. /<server>/TEMP_DIR/.
  • Unzip the archive in that temp directory.
  • Set ORACLE_HOME to your actual Oracle home directory: export ORACLE_HOME=<your oracle home directory>
  • Back up ORACLE_HOME.
  • Back up the JDK, if one is present on the server.
  • Back up the web server domain(s).
  • Navigate to <TEMP_DIR>/WLS_SPB_<patch version>/tools/spbat/generic/SPBAT.
  • Run the apply phase: ./spbat.sh -phase apply -oracle_home <your oracle home directory>
  • Clear the cache, start the domains back up, and test everything before calling it done.

A successful run ends with something like:

SPBAT apply phase has completed successfully Time Taken to run apply phase: 00 hours 09 min 42 secs
Before you run it

These instructions are generic. Some steps may not apply to your specific WebLogic-based product — check your application's own patching documentation for anything product-specific before you run SPBAT against it.

Summary

SPBAT does the heavy lifting, but the manual part — staging the patch, setting ORACLE_HOME correctly, and backing up before you touch anything — is where a rushed patch cycle turns into a rollback. Budget the time for the backups; the apply phase itself is usually done in minutes.
